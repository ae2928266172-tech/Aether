# 上线配置

正式部署（云服务器）时按这里设置。本机试用用 `start.ps1`，不要拿它当正式部署。

## 必须设置的环境变量

| 变量 | 说明 |
|---|---|
| `SHOUYIN_ENV=production` | 打开正式环境安全检查。缺下面任何一项、或还有账号用默认/简单密码，服务端拒绝启动并说明原因 |
| `SHOUYIN_SECRET` | 登录签名密钥，至少 32 位随机字符：`python -c "import secrets;print(secrets.token_hex(32))"`。换了它所有人要重新登录 |
| `DATABASE_URL` | 正式用 PostgreSQL：`postgresql+psycopg://用户:密码@主机:5432/库名` |
| `SHOUYIN_MEDIA` | 商品图片目录，放在数据盘上并纳入备份 |
| `WECHAT_APPID`、`WECHAT_SECRET` | 小程序账号。没设时顾客登录返回“小程序尚未配置” |

网页版顾客免登录（没有小程序时用本机随机标识登录）只在 `SHOUYIN_ENV=dev` 或 `test` 时开放；
不设或设成 production 都是关闭的，部署时漏设环境变量也不会打开。

## 上线前要做的

1. 用 admin 登录后台，右上角改密码（或启动前设 `SHOUYIN_ADMIN_PASSWORD`，只在第一次建库时生效）。
2. 删除或停用演示账号 store1、store2（演示数据只用于试用）。
3. 按实际人员建账号、角色、门店。用默认或过于简单的密码登录时，后台和收银页都会提醒修改。
4. 备份：PostgreSQL 用 `pg_dump` 每天定时备份并异地保存，商品图片目录一起备份；至少演练一次恢复。
   SQLite（本机试用）用仓库里的 `install_backup_task.ps1`，见 README。

## 并发与数据库

- 收款、退款、库存单据都带请求号，重复点击、断网重试只生效一次；请求号会核对操作人、门店、订单和内容。
- `backend/tests/test_concurrency.py` 起真实服务端，24 个请求同时打：两台收银机同时卖同一商品、
  库存不够时不超卖、重复点击收款、同时退同一单、重复退款。设 `TEST_PG_URL` 时在 PostgreSQL 上再跑一遍。
- 全部测试也能在 PostgreSQL 上跑：`TEST_DATABASE_URL=postgresql+psycopg://… python -m pytest`。
- 数据库结构目前靠启动时自动补字段（只加不删不改）。正式积累数据后，改表结构前先备份；
  需要改字段类型或删字段时再引入 Alembic 做版本升级和回滚。

## 关键操作日志

后台“系统 › 操作日志”：改价、商品和库存品修改、角色权限、账号、门店设置、业务规则、库存单据、单据作废、退款，
记录谁、什么时候、改前改后。只有有账号管理权限的人能看。
