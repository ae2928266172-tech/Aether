# 代码审查处理记录（2026-11-14）

Aether 转来一份外部代码审查。逐条核实后的处理结果如下。测试从 28 个增加到 37 个，全部通过；前端改动在浏览器里逐项验证过。

## 已修复

| 审查编号 | 问题 | 处理 |
| --- | --- | --- |
| A1 / P0-1 | 退款金额可以和退货件数脱钩，订单被标成“已全额退款”但钱没退完 | 属实。退款金额现在必须等于本次退货商品的实收金额，传了不一致的金额直接拒绝 |
| A2 / P0-2 | 现金“实收”乱填时被当成“实收 = 应收”，找零显示 0 | 属实。实收、改应收、自定折扣填的不是数字时提示并拦住，不提交 |
| A3 / P0-3 | 后台清空或乱填折扣 / 调低上限会悄悄变成“不限”；售价留空变成 0 元 | 属实。角色和账号的优惠上限、商品售价 / 成本 / 扣减量都必须是合法数字；0 元售价要二次确认。“留空 = 不限 / 同角色”保留，但输入框里写明了 |
| A4 / P0-4 | 退款弹窗默认全退，误点就是整单退款 | 改为默认 0 件，另加“全部退”按钮；确认按钮防连点 |
| B1 / P1-2 | SQLite 两台设备同时写可能报 database is locked | 加了 30 秒等待。PostgreSQL 下的行锁要到部署时在真实库上验证（见“未处理”） |
| B2 / P1-3 | 打印重发会重复计数，重发的那张被标成【补打】 | 属实。打印次数和日志改为小助手回报“已打印”时才记，重复回报只记一次；重发不再响铃 |
| B3 / P1-3 | 一张坏小票会卡住整个打印队列 | 属实。生成失败的任务标记为失败并跳过；同一张最多发 3 次 |
| B4 / P1-4 | 轮询没有在途锁，响应慢时同一批订单响铃、打印两次 | 属实，已加锁；切换门店时丢弃旧门店的结果。另外修了一个审查没提到的问题：门店还没有任何订单时，第一张新订单不会响铃 |
| B5 / P1-5 | 收款成功后打印失败，提示看起来像收款失败 | 属实。现在分开提示：“收款已成功，但小票没打出来……不要重新收款” |
| P0-5 | 没有 PostgreSQL 驱动 | 已加到 requirements.txt |
| 凭据 | 登录签名密钥文件在 OneDrive 同步目录里 | 改放本机 `%LOCALAPPDATA%\shouyin\secret.key`，旧文件已删除 |
| P1-6 | 登录没有失败次数限制 | 同一账号 10 分钟内错 5 次，锁 10 分钟 |
| P0-7 | 二维码用当前打开后台的地址生成，本机 / 内网地址生成的码顾客扫不开 | “业务规则”里新增“顾客访问网址”；没填且用本机 / 内网地址时，二维码窗口会警告 |
| P1-7（部分） | 后台没有表单校验、保存可连点 | 名称必填、金额必须是数字；分类 / 供应商 / 库存品保存防连点 |
| D | 两处测试写成了 `==` 而不是 `assert` | 已改成真正的断言 |

## 核实后不成立

- **“启动时自动补字段会拼出两个 DEFAULT，加布尔字段必然报错”**：不成立。那行代码的运算优先级没有问题，演示库就是靠它从旧版本升级上来的。现已改成更直白的写法，并补了一个升级测试（含布尔、数字、文字默认值）。

## 有意不改

- **打开页面前就已存在的订单不响铃、不自动打印**：这是有意的，否则每次刷新页面都会把旧订单重打一遍。这些订单在“待接单”里和角标上都看得到。
